# Bounded Composition candidate retrieval

Status: **PR candidate for PRIME review**. Base: COMPOSITOR `origin/main` at `ae8de4721515eed2ece377ae147b13768598b067`. PRIME leased this record, `src/compositor/candidate_retrieval.py`, and its synthetic test after ARCHITECTURE assigned stateless package-local candidate retrieval to COMPOSITOR. Buddy owns session selection, permission, query interpretation, World-lens fusion, cache and model-context invalidation, and final context budget. The merged `project_query` API remains unchanged.

`retrieve_candidates(store, refs, query, audience, max_hits, max_bytes)` takes exact caller-selected package revisions and one literal lexical query. It filters audience **before** matching, ranking, counts, or caps. Ranking is exact resource name, then name substring, then text substring; within a class, occurrence count breaks ties before package ID, revision, and resource ID. Every hit retains the full source-linked resource and an exact package/revision/resource ref. One missing revision produces a typed `missing_revision` diagnostic and no fallback; each ref reports aggregate readiness without exposing raw package issues.

The caller must supply both caps. Hard accepted ranges are 1–50 hits and 1,024–65,536 compact UTF-8 JSON bytes; at most eight exact refs and 200 query characters are accepted. The result includes `truncation.omitted_hits`, `hit_cap_reached`, and `byte_cap_reached`. Whole lower-ranked resources are omitted when either cap binds; source text is never cut. A response whose metadata alone exceeds the byte cap fails explicitly. Byte accounting uses deterministic compact JSON encoding (`ensure_ascii=False`, sorted keys, no whitespace). The final caller/model-context budget remains Buddy's responsibility.
