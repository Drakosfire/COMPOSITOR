# Per-binding rule-use readiness

Status: **COMPOSITOR-only implementation for PRIME review**. Base `eb72ac4cf04a93bc7c448f54395c416c324c359d`. ARCHITECTURE reviewed the contract; PRIME activated the bounded lease. This record does not claim owner product integration or source fidelity.

`assess_rule_use` evaluates one declared rule use from an exact citing resource and package revision, for a named audience and workflow. It returns the existing exact rule `resolution` separately from `use_readiness` (`usable`, `limited`, `unknown`, `unavailable`). A resolved identity is not evidence that the rule is ready for Playing. The result includes issue IDs, reasons, exact package/resource paths, workflow, and linked or bundled mode. Existing `resolve_rule` callers and the coarse package-wide `readiness` remain unchanged.

`usable` means the exact chain resolves for this audience and workflow, every resource in the traversed chain declares positive `review_coverage` for that workflow, bundled review scope was captured, and no applicable issue or coverage gap was found. This is a package review assertion, not an independent proof of source accuracy, legal rights, or general safety. `limited` means a known issue is scoped to the citing resource, bound rule, traversed rule, or proven global scope. `unknown` means the issue's scope or review coverage is not established, including an unscoped diagnostic, legacy bundle without captured review scope, or a rule-use cycle. `unavailable` means the exact declared use is missing, denied, unsupported, or mismatched. Downstream gates must treat unknown conservatively; this module does not authorize a governed World write.

Bundling now copies only selected resources plus their relevant review issues and an explicit complete-scope marker. The copied resource can be assessed after its original package revision is absent. A legacy bundle without that marker returns unknown even when it contains resource review declarations. Linked rules re-evaluate their exact saved revision. Unrelated scoped issues do not limit a bound use. Unscoped diagnostics remain unknown unless they declare proven global scope. The evaluator traverses nested rule references and reports cycles without claiming readiness.

The project-authored fixture witness reproduces the original failure: a linked rule carrying a scoped `interpretation_pending` diagnostic was identity-resolved while its consumer package's coarse Playing readiness was usable. Per-use assessment now reports limited with the inherited issue and exact path. Public tests cover linked/bundled modes, both derived save forms, unrelated and unscoped diagnostics, positive and absent workflow coverage, missing original after bundling, missing linked revision, edition/audience denial, and local rule cycles. No private corpus or provider call is involved.

Author-local verification: `PYTHONPATH=src python3 -m unittest discover -s tests -q` passed 36 tests with one optional dependency skip. A wheel build from a clean `/tmp` source copy passed.
